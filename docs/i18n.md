# Internationalisation (i18n)

SeaCraft supports multiple display languages (`en` and `tr` today) without adding runtime
dependencies or changing machine-readable file formats.

## Architecture

1. **Flat JSON catalogs (`locales/*.json`)**:
   - `locales/en.json` is the source of truth for all translation keys and English strings.
   - `locales/tr.json` holds the matching Turkish translations.
   - Both files use flat dot-separated lowercase ASCII keys (`[a-z0-9._]`) sorted in ASCII alphabetical order.
2. **Compile-time code generation (`crates/seacraft-core/build.rs`)**:
   - Reads `locales/en.json` and `locales/tr.json` using `serde_json` (`[build-dependencies]`).
   - Emits `$OUT_DIR/i18n_generated.rs` containing the compile-time checked `Key` enum and static lookup arrays (`static STRINGS_EN`, `static STRINGS_TR`).
   - Calling `tr.s(Key::...)` or `tr.fmt(Key::..., &[...])` (`crates/seacraft-core/src/i18n.rs`) is type-checked at compile time with zero allocation on static lookups.

## Locale Precedence

`seacraft_core::i18n::resolve_locale` applies the following priority order (highest first):

1. `--lang CODE` CLI flag (`seacraft --lang tr ...` or `seacraft-gui --lang tr`)
2. `SEACRAFT_LANG` environment variable (`SEACRAFT_LANG=tr`)
3. Saved GUI preference in eframe persistence (`Help ▸ Language`, stored via `LanguagePref`: `"auto"`, `"en"`, `"tr"`)
4. Operating system locale (`LC_ALL`, `LC_MESSAGES`, `LANG` on Unix; `GetUserDefaultLocaleName` on Windows)
5. Fallback to English (`Locale::En`)

`--lang` and MCP `locale` take exactly `en` or `tr` (any ASCII case); anything else, including a
region or encoding suffix such as `tr_TR.UTF-8`, fails with a clear error. `SEACRAFT_LANG` also
accepts an OS tag (`tr_TR.UTF-8`); a value naming no supported language is ignored with a warning
(on stderr in the CLI, in the Messages log in the GUI).

On Unix the first of `LC_ALL`, `LC_MESSAGES` and `LANG` that is set and non-empty decides, as
POSIX says: `C`, `C.*` and `POSIX` mean English (so `LC_ALL=C` forces English output), and so does
a language SeaCraft does not have. GNU `LANGUAGE` is not consulted.

## What Is Localized vs. Invariant

| Localized (`--lang`, `SEACRAFT_LANG`, GUI `Help ▸ Language`, MCP `locale`) | Invariant (always English / CAD conventions) |
|---|---|
| Desktop GUI chrome, menus, dialogs, docks, HUD, builder previews | `.fef` and `.seacraft.json` file formats |
| Human-readable CLI tables, summaries, warnings, notes | `seacraft --help`, subcommand/flag names, `--version` |
| Design dossier HTML, linesplan SVG/DXF, curves/wave/plate SVGs | `--json` and `--csv` output schemas and field names |
| Builder offsets HTML/PDF, sheet title blocks, templates PDF/SVG/DXF, plywood panels PDF/SVG/DXF | MCP tool names, JSON schemas, and JSON reply fields |
| `seacraft example --list` text and `DISCLAIMER.md` short notice (`not_validated_note`) | DXF layer names (`CUT`, `MARK`, `STATIONS`, etc.), SI units, naval symbols (`LWL`, `Cb`, `GM`, `LCB`, ...) |
| | Decimal separator: always `.` |

## Adding a Translation Key

1. Choose a descriptive lowercase key following existing prefixes (`menu.*`, `hydro.*`, `report.*`, `cli.*`, etc.) using `[a-z0-9._]`.
2. Add the key and value to **both** `locales/en.json` and `locales/tr.json`.
   - Keep keys sorted alphabetically (`json.dumps(..., indent=2, sort_keys=True, ensure_ascii=False) + "\n"`).
   - Ensure `{placeholder}` names match identically between catalogs.
   - Follow [`docs/i18n-glossary-tr.md`](i18n-glossary-tr.md) for Turkish terminology.
3. Run `cargo xtask i18n` (and `cargo xtask ci`) to verify alignment, placeholder parity, balanced braces and sorting. Embedded DejaVu Sans glyph coverage is the `cargo test` unit test `all_catalog_characters_exist_in_embedded_dejavu_font`, which `cargo xtask ci` runs.

## Adding a New Language

1. Add `locales/<code>.json` containing keys matching `locales/en.json`.
2. Add the new variant to `Locale` in `crates/seacraft-core/src/i18n.rs` (`ALL`, `code`, `native_name`, `parse`, `plural_category`, and `Tr::s`).
3. Update `crates/seacraft-core/build.rs` to read `locales/<code>.json` and emit its static array.
4. Update `step_i18n` in `xtask/src/main.rs` (`required_complete`) once the catalog is 100% translated.
5. Add `"<code>"` to `locale_prop()` in `crates/seacraft-cli/src/mcp.rs` and CLI/GUI help strings.
6. Verify every character in the new catalog exists in the embedded PDF font (`seacraft_core::i18n::tests::all_catalog_characters_exist_in_embedded_dejavu_font`).

## Contributor Rules

- **Turkish casing:** Never call Rust's `.to_uppercase()` or `.to_lowercase()` on translated strings. Standard Unicode case folding maps `i` to `I` instead of `İ`, and `I` to `i` instead of `ı`. Always store exact casing in `locales/tr.json`. `cargo xtask i18n` flags every such call in `crates/*/src` outside `#[cfg(test)]` modules, comments and string literals; text that is never translated (a file name, a tool argument) is marked with `// i18n-casing: not translated (why)` on the line or the line before.
- **Messages from computations:** A warning or note that core code raises without knowing the reader (method-validity ranges, wave notes, loading and damage warnings) is a `seacraft_core::i18n::Msg`: a key and its formatted arguments. Every human-readable output renders it with its own `Tr` (`msg.render(tr)`); `Display` and `Serialize` give English, so `--json`, MCP replies and saved files do not change with the language. A name that is itself translated (a sheet name, a cutting plane) goes in with `arg_msg`, so it follows the reader's language too. Never match on a message's text; compare `msg.key()`.
- **PDF font glyphs:** Any character placed in `locales/*.json` must exist in the embedded `DejaVuSans.ttf`; `all_catalog_characters_exist_in_embedded_dejavu_font` enforces this in CI.
- **No raw HTML in catalogs:** Never put raw HTML tags or entities in `locales/*.json`. Escape dynamic values and translated strings in Rust (`esc(...)`).
- **Disclaimers:** Never soften, omit, or imply validation/approval in translations of `disclaimer.not_validated` (`DISCLAIMER.md`).
- **Testing:**
  - `cargo xtask i18n` checks JSON validity, duplicate keys, key syntax, ASCII sorting, empty values, unbalanced braces, orphan keys, missing required keys, `{placeholder}` parity, and case changes in source. `crates/seacraft-core/build.rs` also fails the build on a missing or orphan `tr` key, and `Tr::fmt` debug-asserts that every placeholder got a value.
  - Existing English CLI integration tests in `crates/seacraft-cli/tests/` set `SEACRAFT_LANG=en` so they are deterministic on any host OS locale.
